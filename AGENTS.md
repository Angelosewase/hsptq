# AGENTS.md

## What this is

TypeScript monorepo (Turborepo + pnpm workspaces) for a **Hospital Queue & Scheduling System** ("hsptq"). The product spec is `mvp-spec.md` — read it before building any app functionality. The plan: three thin clients (Expo mobile app, USSD gateway, staff web dashboard) behind one core API; **phone number is the universal patient identity** across channels. `apps/web` and `apps/docs` are still stock create-turbo/Turborepo placeholder pages, not yet the real dashboard.

## Toolchain

- pnpm (pinned `11.25.0` via `packageManager`), Node >= 24. Use pnpm, never npm/yarn.
- Workspaces: `apps/*` (`api` — standalone Hono API service; `web`, `docs` — Next.js 16, React 19, TypeScript 7, ESLint 10) and `packages/*` (`@repo/ui`, `@repo/eslint-config`, `@repo/typescript-config`).

## Commands (run from repo root) (`pnpm` -> `turbo run`)

- `pnpm dev` — dev servers for all apps: web on :3000, docs on :3001, api on :3002 (persistent, uncached).
- `pnpm build` — production builds.
- `pnpm lint` — ESLint. Apps run with `--max-warnings 0`; a single warning fails.
- `pnpm check-types` — Next apps run `next typegen && tsc --noEmit`.
- `pnpm format` — Prettier `--write` on `**/*.{ts,tsx,md}`.
- Single package: `pnpm --filter web <script>` or `pnpm turbo run <script> --filter=<pkg>`.

## Gotchas an agent would otherwise get wrong

- `apps/api` is a standalone Hono service (not Next.js): `dev` is `tsx watch src/index.ts` (port 3002), `build` is `tsup` → `dist/`, `check-types` is plain `tsc --noEmit` (no `next typegen`), `test` is vitest. Routes use `@hono/zod-openapi` (paths like `/visits/{id}/status`, `.openapi("Name")` for schema refs) mounted under `/api` via an `OpenAPIHono` sub-app; docs at `/api/doc`, Swagger UI at `/api/ui`.
- Prisma 7 specifics in `apps/api`: no `url` in `schema.prisma` datastore; connect via driver adapter (`@prisma/adapter-pg`) passed to `new PrismaClient({ adapter })` (see `src/lib/prisma.ts`). CLI config lives in `apps/api/prisma.config.ts` (needs `DATABASE_URL` for migrate/db commands; `prisma generate` works without it via a fallback string). The client is generated to `apps/api/src/generated/prisma` — gitignored, regenerated by `postinstall` on `pnpm install` or `pnpm --filter api db:generate`. Import it as `../generated/prisma/client`, not `@prisma/client`.
- Env for the API: copy `apps/api/.env.example` to `apps/api/.env` for local dev (loaded by `dotenv/config`); `PORT` defaults to 3002.
- `@repo/ui` has **no build step**: its `exports` map `./*` → `./src/*.tsx`, so apps import raw TSX source files (e.g. `@repo/ui/button`). Add components as new files in `packages/ui/src/`; there is no index barrel.
- `check-types` depends on `next typegen` output (`.next/types`); plain `tsc --noEmit` without it can fail in the Next apps.
- Share ESLint config by extending `@repo/eslint-config` (base/next-js/react-internal) rather than defining rules per app.
- Shared tsconfigs come from `@repo/typescript-config` (`base.json` sets `strict`, `noUncheckedIndexedAccess`).
